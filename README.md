# solve — восстановление функции распределения частиц по размерам из лидарных данных

Инверсия лидарных коэффициентов в распределение частиц по размерам `n(r) = dN/dr`
методом разложения по базисным B-сплайнам с регуляризацией по кривизне
и усреднением по ансамблю окон `[r0, r1]`.

> **Подробная документация** — [docs/GUIDE.md](docs/GUIDE.md): физическая
> постановка, метод, все режимы и форматы данных, полный справочник CLI,
> устройство кода, ограничения и примеры.

## Постановка задачи

Измерены (набор может быть любым, но в задании — 5 коэффициентов):

| Тип | Длины волн, нм |
|-----|---------------|
| коэффициент обратного рассеяния β | 355*, 532, 1064 |
| коэффициент ослабления α | 355, 532 |

\* в исходном задании указано «533 нм» — здесь трактуется как опечатка
стандартного трёхволнового лидара 355 нм; набор длин волн полностью
определяется входными данными и нигде не зашит в код.

Искомая функция распределения ищется в виде разложения

```
F(r) = Σᵢ Cᵢ Bᵢ(r),   r ∈ [r0, r1],
```

где `Bᵢ` — базисные B-сплайны степени `k ∈ {1, 2, 3, 4}` на логарифмически
эквидистантной сетке узлов. Число базисных функций по умолчанию равно числу
измерений M (в задании M = 5) и настраивается флагом `--n-basis N`. Восстанав-
ливается **объёмное распределение `F(r) = dV/dln r`** (объём частиц на
логарифмический интервал радиуса; в выводе — мкм³/см³); числовое распределение
получается из него как `n(r) = dN/dr = F(r)·3/(4π r⁴)` (r в мкм).

**Граничные условия.** Из базиса исключаются первая и последняя функции
(B₀ и B_{M-1}) — в зажатом (clamped) базисе только они отличны от нуля на
концах интервала. Поэтому каждое элементарное решение (каждая базисная
функция, а значит и любое разложение по базису) обращается в ноль на
границах: `F(r0) = F(r1) = 0`. В разложении остаётся N−2 функции
(при N = 5 — три), где N — число базисных функций (`--n-basis`).
Отключить условие можно флагом `--no-zero-boundary`.

Прямая задача — интегральное уравнение

```
gⱼ = ∫_{r0}^{r1} Kⱼ(r)·q(r)·Σᵢ Cᵢ Bᵢ(r) dr = (A C)ⱼ,
   Aⱼᵢ = ∫ Kⱼ(r)·q(r)·Bᵢ(r) dr,    q(r) = 3/(4πr⁴),
```

с ядрами (Mie, через `miepython`):

```
ослабление:       Kⱼ(r) = π r² q_ext(r, λⱼ, m)
обратное рассеяние Kⱼ(r) = (r²/4) q_back(r, λⱼ, m)
```

Здесь `q_back` в `miepython` определён через амплитуду обратного рассеяния
`q_back = |Σ (2n+1)(-1)ⁿ (aₙ - bₙ)|² / x²`, откуда дифференциальное сечение
обратного рассеяния на стерадиан `C_back = q_back·r²/4` (проверено по
рэлеевскому пределу).

**Единицы входных данных (согласованы):** β — 1/(м·ср), α — 1/м.
Ядра возвращаются в физических единицах (r в мкм переводится в метры):
`K_ext` — м², `K_back` — м²/ср.  Восстановленное распределение F(r) = dV/dln r
внутри считается на кубометр воздуха (мкм³/м³); в выводе объёмные величины
приводятся к мкм³/см³, числовая концентрация — к см⁻³. Из него выводятся
числовая концентрация N (см⁻³), объёмная концентрация C_v (мкм³/см³),
средний объём частиц ⟨V⟩ (мкм³), эффективный радиус r_eff (мкм) и параметры
логнормальных мод — см. раздел «Выходные данные».

## Метод

1. **Базис.** Для каждого окна `[r0, r1]` строится зажатый B-сплайновый базис
   степени `k` из M функций; внутренние узлы — логарифмически равномерно.
   Крайние функции (B₀ и B_{M-1}) исключаются: каждая базисная функция
   равна нулю на границах, т.е. n(r0) = n(r1) = 0 (флаг
   `--no-zero-boundary` отключает).
   При M = 5 для степени 4 внутренних узлов не остаётся: базис вырождается
   в полиномы Бернштейна степени 4 на весь интервал (корректный предельный
   случай, число функций по-прежнему равно M).
   Квадратуры Гаусса–Лежандра дробятся по узлам базиса и логарифмическим
   подсегментам, чтобы разрешить осцилляции ядер Mie.

2. **Матрица A.** Ядра Kⱼ(r) считаются через `miepython` один раз на плотной
   таблице по r (шаг по параметру размера x ≈ `--dx-max`) и интерполируются
   кубическими сплайнами в логах — это ускоряет перебор окон на порядки.

3. **МНК с регуляризацией по кривизне** (вторая разность коэффициентов):

   ```
   min ||W (A C - g1)||² + γ² ||L C||²,    L — матрица вторых разностей,
   ```

   веса `W = 1/g1` по умолчанию (относительная невязка, согласована с Err).
   При `--nonneg` накладывается `C ≥ 0` (тогда и `F(r) ≥ 0`).

4. **Параметр регуляризации** `γ`:
   - `--gamma-select fixed` (по умолчанию): `γ = γ_rel · ||A||₂`,
     `γ_rel = --gamma-rel 0.1`; одинаковая нормировка для всех окон;
   - `--gamma-select cv`: leave-one-out кросс-валидация по относительной
     невязке (автовыбор γ);
   - `--gamma-select err`: минимум невязки Err (как в исходном описании;
     при M измерений = M неизвестных вырождается в точную интерполяцию).

5. **Невязка** (критерий качества окна):

   ```
   Err = Σᵢ |gᵢ - g1ᵢ| / g1ᵢ
   ```

6. **Ансамбль.** Перебираются окна (r0, r1), степени сплайнов **и сетка
   показателя преломления m** (декартово произведение `--m-reals` ×
   `--m-imags`; в табличном режиме — только те m, для которых есть таблицы).
   Для каждого m строится своя таблица ядер. Берутся G
   решений с наименьшей невязкой (`--best G`). По каждому
   восстанавливается `F(r)`; итоговая функция — среднее по этим G
   решениям с нормировкой по покрытию: в точке r усредняются только
   решения, чьё окно содержит r (точки вне всех окон помечаются NaN).
   **Итоговый показатель преломления — среднее по тем же G лучшим
   решениям** значений m (среднее комплексных чисел).

7. **Сглаживание среднего.** Поточечное среднее решений изломается на
   границах окон (в точке r меняется набор покрывающих решений). Эта
   ступенчатая зависимость сглаживается кубическим сглаживающим сплайном
   (`scipy.interpolate.make_smoothing_spline`) в нормированных координатах:
   аргумент — логарифм радиуса, приведённый к [0,1], значения — F/|F|max,
   поэтому относительный параметр `--smooth-lam` (по умолчанию 1e-4)
   безразмерен и переносится между наборами данных. Веса точек —
   кратность покрытия, крайние точки покрытия притягиваются к сырым
   значениям (без артефактов на границах). Отключить сглаживание —
   `--no-smooth`; сырое (несглаженное) среднее доступно в JSON
   (`n_avg_raw`) и на графике пунктиром.

8. **Анализ мод.** По усреднённому объёмному распределению F(r) оцениваются
   параметры логнормальных мод (в dV/dln r):
   - **fine** — диапазон `r ∈ [r_cov_min, r_split]` (по умолчанию
     `r_split = 0.5` мкм, флаг `--r-split`): `Vf, rm_f, σf`;
   - **coarse** — `r ∈ [r_split, r_cov_max]`: `Vc, rm_c, σc`;
   - **общая оценка** — одна логнормаль по всему покрытому диапазону:
     `V, rm, σ`.
   Значения V — интегралы F по соответствующим диапазонам (мкм³/см³);
   rm, σ — из взвешенного МНК-фита логнормали в координатах (ln r, ln F)
   (веса — кратность покрытия, точки с F ≤ 0 исключены). Если фит
   вырождается (например, для бимодального суммарного распределения
   парабола в ln-координатах получается выпуклой — одной логнормалью
   форму не описать), rm, σ оцениваются по объёмным моментам
   (rm = exp⟨ln r⟩_V, σ = exp(СКО ln r)_V) — оценка выводится всегда,
   способ помечается в таблице и в JSON (`method`: `fit` или `moments`).

Для реальных данных без явных `--m-reals/--m-imags` сетка строится
автоматически вокруг m из файла. Для демо по умолчанию используется сетка
Re = 1.40/1.45/1.50 × Im = −0.01/−0.005/0. **В табличном режиме** (`--tables`)
сетка m всегда берётся из самих таблиц (подкаталоги `mre_*_mim_*`),
а `--m-reals/--m-imags` её только сужают.

## Установка и запуск

**Способ 1 — uv (рекомендуется):**

```bash
uv sync                                   # создать окружение (numpy, scipy, matplotlib, miepython)
uv run python -m solve                    # демонстрация на синтетических данных + график
uv run python -m solve --data data.json   # по реальным измерениям
# или (то же самое):
uv run solve
```

Пакет также ставит утилиту **`mkbase`** — сборку базы сечений
(`x, Cext, Cabs, Cback, Qext, Qabs, Qback`) из каталога с результатами
расчётов ADDA: `uv run mkbase results_aggl -o base` (или `mkbase …` после
установки). Флаг `--nx N` переинтерполирует все таблицы (пошape и `average/`) —
на лог-эквидистантную сетку из `N` узлов по каждой группе `(mre, mim)`.
Подробнее — [docs/GUIDE.md](docs/GUIDE.md), раздел 8.

**Способ 2 — без uv (pip + venv):**

Зависимости перечислены в `requirements.txt` (пиннинг через
`uv pip compile pyproject.toml`):

```bash
python3 -m venv .venv                     # создать окружение
source .venv/bin/activate                 # активировать (Windows: .venv\Scripts\activate)
pip install -r requirements.txt           # установить зависимости (numpy, scipy, matplotlib, miepython)
pip install .                             # установить сам пакет
solve --help                              # или: python -m solve
```

`pip install .` собирает пакет через PEP 517-бэкенд `uv_build`, который pip
сам скачает с PyPI — отдельно ставить uv не нужно. Если нужна разработка
без переустановки после правок, ставьте в режиме редактирования:
`pip install -e .` (зависимости можно не ставить отдельно — pip
подтянет их сам из `pyproject.toml`).

Возможна также установка **без сборки пакета** — достаточно зависимостей
из `requirements.txt` и добавления `src` в путь поиска модулей:

```bash
git clone <этот-репозиторий> && cd solve
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=src python -m solve           # *nix/macOS
# Windows (PowerShell): $env:PYTHONPATH="src"; python -m solve
```

Требуется Python ≥ 3.14 (см. `pyproject.toml`).

Тесты:

```bash
uv run python tests/test_smoke.py        # с uv
python tests/test_smoke.py               # без uv (в активированном venv)
uv run pytest tests/ -q                  # если установлен pytest
pytest tests/ -q                         # без uv (в активированном venv)
```

## Формат входных данных

```json
{
  "m": {"real": 1.45, "imag": -0.005},
  "backscatter": {
    "wavelengths_nm": [355, 532, 1064],
    "coefficients": [1.24e-5, 1.33e-5, 8.75e-6]
  },
  "extinction": {
    "wavelengths_nm": [355, 532],
    "coefficients": [3.78e-4, 4.10e-4]
  }
}
```

**Единицы коэффициентов согласованы:** β — 1/(м·ср), α — 1/м (см. пример).
Все коэффициенты должны быть положительными. Готовый пример —
`examples/input_example.json` (реалистичные значения: β ~ 10⁻⁵ 1/(м·ср),
α ~ 10⁻⁴ 1/м). Поле `units` — справочное, значения коэффициентов не
конвертируются.

Поле `m` — **априорная оценка комплексного показателя преломления** частиц
(`m = n − ik`). Оно не подставляется в ядра как «истинное» значение, а задаёт
центр сетки перебора: если не заданы явные `--m-reals` / `--m-imags`, строится
сетка `Re(m) ∈ {0.95, 1.0, 1.05}·Re(m₀)` и `Im(m) ∈ {−|Im(m₀)|, −|Im(m₀)|/2,
0}` (до 9 значений `m`). Для каждого `m` сетки обратная задача решается со
своими Mie-ядрами, решения ранжируются по невязке `Err`, и по `G` лучшим
усредняется в том числе и показатель преломления — итоговое `m_avg`.

`Im(m) ≤ 0` — поглощающая среда (конвенция miepython). Сетку можно задать
явно и сузить, если аэрозоль известен хорошо:
`--m-reals 1.4 1.45 1.5 --m-imags -0.01 -0.005 0`.

## Табличный режим ядер (--tables)

Вместо расчёта ядер через miepython можно подать **внешние таблицы сечений**
`C_ext(x)` и `C_back(x)` (в мкм²) как функции безразмерного параметра размера
`x = 2πr/λ`, снятые при **эталонной длине волны `λ_ref = 2π` мкм** (при этом
абсцисса `x` численно равна радиусу `r` в мкм). Таблицы берутся в формате,
который создают `mkbase` (GUIDE, раздел 8) и `mkbase_spheres`. Они задают
физическую модель частиц (в том числе показатель преломления `m`) напрямую,
поэтому miepython в табличном режиме не используется, а сам показатель
преломления в ядрах не участвует — он остаётся только как метка каталога.

Поскольку сечение ∝ λ², при использовании на длине волны канала λ оно
пересчитывается как `C·(λ/λ_ref)²`: так таблица, снятая при `λ_ref = 2π`,
даёт правильные ядра для 355/532/1064 нм. Численно множитель `(λ/λ_ref)²`
для 355, 532, 1064 нм равен 3.19·10⁻³, 7.17·10⁻³, 2.87·10⁻².

**Структура каталога** — `--tables` указывает на каталог с подкаталогами
`mre_<real>_mim_<imag>` (например `base/average` или `base/shapeNN` — то, что
создают `mkbase` и `mkbase_spheres`), внутри каждого — `data.txt`:

```
base/average/
  mre_1.45_mim_0.00000/
    data.txt
  mre_1.45_mim_0.01680/
    data.txt
  ...
```

- имя каталога — `mre_<real:.2f>_mim_<imag:.5f>` (как в `mkbase`);
  отрицательный ноль нормализуется (`mim_0.00000`);
- `data.txt` — таблица с заголовком `# x Cext Cabs Cback Qext Qabs Qback [n]`
  (заголовок — строка, у которой первый токен после `#` равен `x`) и
  числовыми столбцами; читаются `x`, `Cext` (ослабление) и `Cback` (обратное
  рассеяние) — **выбор по имени колонки**, остальные (`Cabs`, `Q*`, `n`)
  игнорируются. Комментарии (`# Units: ...`, `# Smoothed ...` у
  `mkbase_spheres`) и пустые строки пропускаются;
- `x` строго возрастает, `C > 0`, точек не меньше трёх;
- таблица снята при `λ_ref`; `λ_ref` задаётся `--table-ref-lambda-um`
  (по умолчанию `2π` мкм), а на длину волны канала сечение пересчитывается
  множителем `(λ/λ_ref)²`;
- сечение `C_back` — **дифференциальное сечение на стерадиан** `dσ/dΩ(180°)`
  (согласовано с β [1/(м·ср)]); так его пишут `mkbase` (ADDA: `s11(θ) = dσ/dΩ`)
  и исправленный `mkbase_spheres`. Старые таблицы `mkbase_spheres`/`miedir`
  содержат `4π·dσ/dΩ` — для них укажите `--table-cback 4pi` (иначе ядра beta
  в 4π больше нужного и восстановление уходит в мелкие радиусы);
- отсутствие каталога для нужного `m` — ошибка; выход `x` за пределы
  таблицы — ошибка (экстраполяция только с `--table-extrapolate`);
- `--tables` должен указывать на `base/average` или `base/shapeNN`, а не на
  корень `base` (в нём лежат и `average/`, и `shape*/`): в этом случае
  выдаётся ошибка с подсказкой.

**Разрешение сетки.** Для сферических таблиц лог-сетка должна разрешать рипл
Mie: при `Δx ≳ 0.5` медианная ошибка мала, но в резонансах ядро отличается
в разы, и результат инверсии смещается. Практика — `Δx ≲ 0.1` в верхней части
диапазона: для `x = 0.01…80` это ≈ 8000 узлов
(`mkbase_spheres --nx 8000`), для `x = 0.3…34` — `mkbase --nx 500`.
Сглаживание таблиц (`mkbase_spheres --smooth`) тоже смещает результат — для
ядер лучше его не включать. Проверить конкретную базу:
`python tests/compare_tables_mie.py <каталог>`.

**Ограничение по радиусу.** Таблица покрывает `x` до некоторого `x_max`
(в вашем случае — 82). Поскольку `r = x·λ/(2π)`, максимальный радиус,
который может описать канал, равен `r_max = x_max·λ/(2π)`:

| λ, нм | r_max при x_max = 82, мкм |
|-------|---------------------------|
| 355   | 4.63 |
| 532   | 6.94 |
| 1064  | 13.9 |

Эффективный верхний предел окон `r1_max` ограничивается минимумом по всем
каналам (при `x_max = 82` это 4.63 мкм — коротковолновые каналы 355 нм
«режут» диапазон). Код автоматически урезает `r1_max` и печатает таблицу
покрытия по каналам; при `r1_max < r1_min` выдаётся ошибка (расширьте
таблицы по x или уменьшите `--r1-min`).

**Сетка m берётся из таблиц.** Перебор идёт только по тем значениям
`m`, для которых в каталоге есть `mre_*_mim_*` (то есть посчитаны
таблицы). Флаги `--m-reals/--m-imags` (если заданы) сужают этот набор;
значения, для которых таблиц нет, в перебор не попадают. Для каждого `m`
загружается свой набор таблиц, решения ранжируются по невязке `Err`, а
`m_avg` усредняется по `G` лучшим — как в Mie-режиме. В демо-режиме
«истинный» `m` тоже выбирается из табличных (по умолчанию — ближайший к
`1.45 − 0.005j`); если заданы оба `--m-real/--m-imag`, они должны
соответствовать табличному `m`.

Интерполяция таблиц выполняется в логарифмических координатах
(`ln x`, `ln C`) кубическим сплайном (как в `KernelTable`). Шаг таблицы по `x`
должен разрешать осцилляции (рипл) факторов Mie: при крупном шаге
(max Δx > 1) выдаётся предупреждение. Демо-режим без `--data` синтезирует
измерения из таблиц опорного `m`.

## Выходные данные

- на экран — таблица лучших вариантов (ранг, m, k, r0, r1, γ, Err),
  средний показатель преломления ⟨m⟩, таблица `F = dV/dln r` в ключевых
  точках, согласие по каналам `g` vs `g1`, **параметры мод**;
- **интегральные характеристики** восстановленного распределения
  (по покрытой лучшими решениями области, F ≥ 0 по физ. смыслу):

  | Величина | Формула | Единицы |
  |----------|---------|---------|
  | объёмная концентрация C_v | ∫ F dln r | мкм³/см³ |
  | числовая концентрация N | ∫ F·3/(4πr⁴) dr | см⁻³ |
  | средний объём частиц ⟨V⟩ | C_v / N | мкм³ |
  | эффективный радиус r_eff | ∫r³n dr / ∫r²n dr | мкм |

  (1 мкм³ = 10⁻¹⁸ м³; 1 мкм³/см³ = 10⁶ мкм³/м³.) Дополнительно выводятся
  покрытый диапазон радиусов и доля покрытия сетки.
- **параметры логнормальных мод** (dV/dln r): для каждой моды —
  V (мкм³/см³), rm (мкм), σ. fine: `[r_cov_min, r_split]`; coarse:
  `[r_split, r_cov_max]`; общая оценка — по всему покрытому диапазону;
  rm и σ считаются либо фитом логнормали, либо статистически (по объёмным
  моментам) — выбор через `--modes fit|stat|auto`;
- `result.png` — два панно: log-log график `dV/dln r` (мкм³/см³) (лучшие
  решения, сглаженное среднее; при демо — истинное; сырое среднее
  пунктиром для сравнения) и сравнение `g1` с расчётными `g`; на первом
  панно указано ⟨m⟩;
- `--json` — полные результаты: `m_avg`, `moments`, `modes`, сетка `r`,
  `n_avg` (сглаженное, dV/dln r в мкм³/см³), `n_avg_raw` (несглаженное),
  решения (m, k, r0, r1, γ, Err, коэффициенты C), `g_fit` по каналам.

## Ограничения

С 5 измерениями и 5 базисными функциями восстанавливается только гладкая
огибающая распределения: узкие моды (ln σ ≲ 0.4–0.5) «размазываются».
Амплитуда в центрах мод систематически занижается (эффект сглаживания),
что видно на демо-задаче. При необходимости — увеличивайте число каналов
в данных или меняйте сетку окон `--r0-*`/`--r1-*` под ожидаемый диапазон
размеров.

Показатель преломления восстанавливается с точностью до шага заданной
сетки `--m-reals`×`--m-imags`; если оптимальное m попадает на границу
сетки, расширьте её. Время расчёта растёт пропорционально числу значений
m в сетке (для каждого m строится своя таблица ядер).

Интегральные характеристики считаются по покрытой области; из-за
сглаживания N и C_v, как правило, занижаются (амплитуда F(r) занижается).
Граничные условия `F(r0)=F(r1)=0` (по умолчанию) убирают фиктивный хвост
распределения на краях окон, из-за которого ⟨V⟩ и r_eff завышались, —
с ними оценки ⟨V⟩ и r_eff заметно точнее (см. демо). Цена ограничения —
на одно окно приходится N−2 (при N = 5 — три) коэффициентов вместо N,
невязка Err может слегка возрасти. При N−2 > числу каналов система
становится недоопределённой: решение опирается на регуляризацию
(выдаётся предупреждение). Для более точных величин используйте
`--nonneg` и более широкую сетку окон.

Параметры мод (rm, σ) оцениваются по сглаженному среднему: из-за
ограниченного разрешения (5 измерений) моды «размазываются» — σ, как
правило, завышается, rm смещается к центру масс распределения, а Vf и V
восстанавливаются точнее (см. демо). Это фундаментальное ограничение
постановки, а не ошибка алгоритма.

## Пакетная обработка (--batch)

Флаг ``--batch MEASUREMENTS.txt`` обрабатывает сразу все высоты из одного
файла. Формат — тот же, что в примере ``tests/data/measurements_example.txt``:

```txt
Altitude  b355  b532  b1064 a355  a532
100       9.879211342818602e-06 1.06715705204743e-05  7.002700027432126e-06 0.000302238873845872  0.000327611920803267
...
```

- первая строка — заголовок: ``Altitude`` + имена каналов (любое число);
  имя ``b<нм>`` → обратное рассеяние β, ``a<нм>`` → ослабление α;
  длины волн берутся из имени (355/532/1064 и т.п.), единицы — β [1/(м·ср)],
  α [1/м], как в JSON-режиме;
- каждая следующая строка — ``H  <коэффициенты в том же порядке>``;
- высот может быть сколько угодно, канальный набор — свой на пакет
  (например, 355/532/1064 в β и 355/532 в α, как в примере).

Как работает:

1. **таблица ядер Mie строится один раз** на весь пакет (для каждого m из
   сетки ``--m-reals``/``--m-imags``; в табличном режиме — для каждого m,
   для которого есть таблицы) и переиспользуется для всех высот —
   она не зависит от измеренных коэффициентов;
2. для каждой высоты по своим коэффициентам выполняется полный цикл
   (перебор (m, r0, r1, степень) → ансамбль лучших → восстановленное
   ``dV/dln r``, моменты, моды) — тот же солвер, что и в одиночном режиме;
3. на выходе (каталог ``--batch-out-dir``, по умолчанию — рядом с входным
   txt без расширения) создаются:

   - ``dist_<H>.txt`` — функция распределения (``r, мкм`` | ``dV/dln r,
     мкм³/см³``); в комментарии в начале — высота и входные данные
     (строка измерений);
   - ``moments.txt`` — строка на высоту: ``H  Vf  Vc  V  rmf  rmc  rm
     reff  N  sigma_f  sigma_c  sigma`` (объёмы — мкм³/см³, радиусы и
     reff — мкм, N — см⁻³, σ — безразм.);
   - ``refractive.txt`` — строка на высоту: ``H  Re(m)  Im(m)``;
   - ``errors.txt`` — строка на высоту: ``H`` + относительная ошибка по
     каждому каналу (``|β_fit−β|/β``) + суммарная ``Err``;
   - ``lidar_ratios.txt`` — восстановленное лидарное отношение S = α/β по
     общим длинам волн каналов (только при ``--lidar-ratio-cons``): строка
     на высоту ``H  S_<нм> ...``;
   - ``plot_<H>.png`` — график распределения и согласия по каналам для
     каждой высоты.

**Ограничение плавности лидарного отношения (--lidar-ratio-cons)** —
по умолчанию выключено. Лидарное отношение S_λ = α_λ/β_λ не должно
испытывать сильных вариаций с высотой. При включении ранжирование решений
каждой высоты дополняется штрафом за отклонение S от опорного профиля —
сглаженной по высотам оценки S:

    score = Err + w · mean_λ |ln S_сол(λ) − ln S_ref(h, λ)|,

где w = ``--lidar-ratio-w``. Оценка S для высоты — медиана по top-K
решениям-кандидатам; опорный профиль строится кубическим сглаживающим
сплайном по высоте (при ≥ 5 высот) либо скользящей медианой по окну из
соседних высот и уточняется итеративно (до ``--lidar-ratio-iter``
итераций, досрочно — при стабилизации состава лучших G). Переранжирование
меняет и ансамбль лучших решений (и, как следствие, ⟨m⟩, моменты, моды),
поэтому ограничение входит в основной результат, а не только в
постобработку. Требует ≥ 2 высот и хотя бы одной общей длины волны в
каналах β и α; в противном случае печатается предупреждение и ограничение
не применяется.

Остальные флаги (``--m-reals/--m-imags``, ``--r0-min/--r0-max/--nr0``,
``--r1-*``, ``--degree/--n-basis``, ``--gamma-*``, ``--modes``) действуют
как в обычном режиме и задаются один раз на весь пакет.

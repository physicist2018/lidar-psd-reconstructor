# csolve — табличный режим solve на C

`csolve` — C11-переписывание **табличного режима** Python-пакета `solve`
(ветка `feat/tabular-cross-sections`): ядра берутся из внешних таблиц сечений
`Cext(x)` / `Cback(x)` (каталог `--tables DIR`), а дальше выполняется тот же
конвейер обратной задачи:

1. загрузка `mre_<real>_mim_<imag>/data.txt`, выбор колонок **по имени** из
   заголовка, интерполяция `ln C` от `ln x` кубическим сплайном not-a-knot;
2. пересчёт сечения на длину волны канала `C·(λ/λ_ref)²`, конвенции
   `Cback`: `dsigma` (по умолчанию) и `4pi`;
3. сетка `m` — из каталогов таблиц (все доступные `m`);
4. автоматическое ограничение `r1_max` по покрытию таблиц `x_max·λ/2π`;
5. таблица ядер на сетке `r` с шагом `dx_max·λ_min/2π`, интерполяция
   `ln K` от `ln r`;
6. B-сплайны на логарифмической сетке, составные квадратуры
   Гаусса–Лежандра, матрицы `A` для всех `(m, окно)`;
7. регуляризованный МНК (`fixed`/`cv`/`err`), перебор окон, ансамбль
   лучших решений, сглаживание, моменты и логнормальные моды;
8. вывод в консоль, JSON и PNG (через gnuplot); весь вывод — на английском.

Mie-режим (`miepython`) в C-версию **не переносился**: ядра берутся только
из таблиц. Пакетная обработка (`--batch`) и ограничение плавности
лидарного отношения (`--lidar-ratio-*`) реализованы.

## Сборка

Make:

```bash
cd csolve
make            # -> csolve/csolve
make test       # юнит-тесты
```

CMake:

```bash
cd csolve
cmake -S . -B build && cmake --build build -j
ctest --test-dir build
```

Требуется C11-компилятор и libm. Для графика — `gnuplot` в `PATH`
(при его отсутствии расчёт завершается, печатается предупреждение).
Разбор аргументов выполняется библиотекой **argtable3 3.3.1**, она лежит
рядом (`third_party/argtable3/`, амальгамация, лицензия BSD-3) — внешние
зависимости не нужны, ни CMake, ни Make их не ищут.

## Запуск

```bash
# демонстрация на синтетических данных из таблиц base/average
./csolve --tables ../base/average --table-extrapolate \
         --r1-min 0.5 --r1-max 1.9 --json out.json

# реальные измерения (формат JSON как у solve)
./csolve --tables ../base/average --data ../examples/input_example.json ...

# таблицы miedir записаны в конвенции Cback = 4π·dσ/dΩ
./csolve --tables ../miedir --table-cback 4pi --r1-min 1 --r1-max 5.6

# пакетно: все высоты из txt, таблицы ядер и матрицы A — один раз на пакет
./csolve --batch ../tests/data/measurements_example.txt \
         --tables ../base/average --table-extrapolate \
         --r1-min 0.5 --r1-max 1.9 \
         --lidar-ratio-cons --batch-out-dir out_batch
```

Поддерживаются флаги табличного режима `solve`, влияющие на ядра и
обратную задачу: `--data`, `--tables`, `--table-extrapolate`,
`--table-ref-lambda-um`, `--table-cback`, `--degree`, `--n-basis`,
`--r0-min/--r0-max/--nr0`, `--r1-min/--r1-max/--nr1`, `--min-ratio`,
`--best`, `--gamma-select/--gamma-rel/--gamma-min/--gamma-max/--ngamma`,
`--nonneg`, `--no-zero-boundary`, `--no-smooth`, `--smooth-lam`,
`--r-split`, `--modes`, `--absolute`, `--dx-max`, `--nr-out`,
`--quad-order`, `--log-span`, `--m-real/--m-imag`,
`--noise`, `--seed`, `--out`, `--plot-format`,
`--plot-dpi`, `--plot-font-size`, `--no-plot`, `-h/--help`.
Полная справка: `./csolve --help`.

Сетка `m` всегда берётся из таблиц целиком; флаги `--m-reals/--m-imags`
(`solve` сужает ими перебор) в `csolve` не поддерживаются: состав
таблиц и есть набор `m`. Флаги `--m-real/--m-imag` (единственное число)
остались — они задают истинный `m` для демо-данных.

Отличие от Python: разбор аргументов целиком выполнен на argtable3.
Справка `--help` формируется самой библиотекой (`arg_print_syntax` и
`arg_print_glossary`), ошибки — тоже (`arg_print_errors`). Проверки
значений выполняет библиотека: перечисления (`--table-cback`,
`--gamma-select`, `--modes`, `--plot-format`) — через `arg_rex`, а
числовые диапазоны (включая `--degree`) — через установленный на аргумент
`checkfn` с собственным `errorfn`. Обязательность `--tables` задана в
argtable (`mincount = 1`). Все сообщения программы (консоль, ошибки,
подписи графиков, заголовки пакетных файлов) — на английском; русские
остались только в комментариях кода и в документации.
Многозначная опция `--degree`
принимает значения как списком через пробел, так и повтором флага;
поддерживаются также формы `--opt=value`.
Допустимые степени B-сплайнов — `1, 2, 3, 4` (по умолчанию перебираются
все четыре, как в Python).

### Формат графиков и dpi

```bash
./csolve --tables ../base/average --table-extrapolate \
         --r1-min 0.5 --r1-max 1.9 \
         --plot-format pdf --plot-dpi 300 --out out.pdf

# крупные подписи осей и серий на графике
./csolve --tables ../base/average --table-extrapolate \
         --r1-min 0.5 --r1-max 1.9 \
         --plot-font-size 16 --out big.png
```

- `--plot-format png|pdf|svg` (по умолчанию `png`) — тип сохраняемого
  изображения; в пакетном режиме меняется расширение у всех графиков:
  `plot_<H>.<fmt>`, `refractive.<fmt>`, `error.<fmt>`, `volumes.<fmt>`,
  `radii.<fmt>`, `concentration.<fmt>`, `sigma.<fmt>`,
  `lidar_ratios.<fmt>`.
- `--plot-dpi N` (по умолчанию `150`) — разрешение для `png` и `svg`:
  размеры фигур заданы в дюймах, пиксели = дюймы · dpi (при 150 dpi
  размеры прежние: 1300×520 для одиночного режима и 900×720/1200×460 для
  пакетных). Для `pdf` картинка векторная — dpi не влияет (размер в дюймах).
- `--out FILE` — путь графика в одиночном режиме; по умолчанию
  `result.<fmt>`. Тип файла определяется `--plot-format`, а не расширением
  имени, поэтому при несовпадении расширения лучше задать его явно.
- `--plot-font-size S` (по умолчанию `0` — шрифт терминала, 10 pt) — размер
  шрифта подписей осей (`set xlabel/ylabel/x2label`) и легенды серий
  (`set key`) в пунктах, допустимо 4…72. Действует для всех графиков, включая
  пакетные (`plot_<H>.<fmt>` и сводные). Заголовки графиков и подписи
  делений (`tics`) не меняются.

`--no-jit` принимается и игнорируется (Mie-бэкенда нет).

## Пакетная обработка (`--batch`)

Формат txt — как в Python-версии: первая строка-заголовок
`Altitude b<нм>... a<нм>...`, далее строка на высоту:

```txt
Altitude  b355  b532  b1064 a355  a532
100       9.879211342818602e-06 1.06715705204743e-05 ...
500       1.2879211342818602e-05 ...
```

Имена `b<нм>` — обратное рассеяние β [1/(м·ср)], `a<нм>` — ослабление α
[1/м]. Строки-комментарии (`#`) и пустые строки пропускаются.

Как работает:

1. таблицы ядер и **матрицы `A` для всех `(m, окно)` строятся один раз** на
   весь пакет и переиспользуются для всех высот;
2. каждая высота решается тем же `scan_variants` по готовым `A`, затем
   ансамбль/моменты/моды (общий `profile_finalize` с одиночным режимом);
3. без `--lidar-ratio-cons` высоты обрабатываются потоково (пик памяти не
   зависит от числа высот).

Файлы результатов в `--batch-out-dir` (по умолчанию — рядом с входным txt):

| Файл | Содержимое |
|------|------------|
| `dist_<H>.txt` | `r, мкм` \| `dV/dln r, мкм³/см³`; в шапке — высота и входная строка |
| `moments.txt` | `H Vf Vc V rmf rmc rm reff N sigma_f sigma_c sigma` |
| `refractive.txt` | `H Re(m) Im(m)` |
| `errors.txt` | `H` + относительные ошибки по каналам + `Err` (среднее) |
| `lidar_ratios.txt` | `H S_<нм> ...` (только при `--lidar-ratio-cons` и общих λ) |
| `plot_<H>.<fmt>` | компактный график высоты (если не задан `--no-plot`) |
| `refractive.<fmt>` | сводный вертикальный профиль Re(m) и Im(m) по высотам: одна панель, две оси X (низ — Re(m), верх — Im(m)), ось Y — высота |
| `error.<fmt>` | средняя относительная ошибка восстановления `Err`, **в процентах**, по высотам |
| `volumes.<fmt>` | объёмные концентрации `V`, `Vc`, `Vf` по высотам |
| `radii.<fmt>` | радиусы `rmf`, `rmc`, `reff` по высотам |
| `concentration.<fmt>` | числовая концентрация `N` по высотам |
| `sigma.<fmt>` | ширины мод `sigma_f`, `sigma_c`, `sigma` по высотам |
| `lidar_ratios.<fmt>` | лидарное отношение `S_{355}`, `S_{532}` по высотам (если есть общие λ β∩α) |

`<fmt>` — расширение по `--plot-format` (`png`/`pdf`/`svg`).

Сводные графики (всё, кроме `plot_<H>.<fmt>`) устроены одинаково: **ось Y —
высота** (подписана «Высота H, м»), значения — по оси X; несколько серий на
одной панели, логарифмическая шкала X включается автоматически, если все
значения положительны и их размах больше 30x; точки с NaN пропускаются.
Ошибка (`error.<fmt>`) выводится в процентах. Эти графики — дополнение
C-версии (в Python их нет).

Форматирование чисел — `%g`, как `:g` в Python, поэтому текстовые файлы
совпадают с эталоном почти посимвольно. Расширение графиков задаётся
`--plot-format` (`png`/`pdf`/`svg`).

**`--lidar-ratio-cons`** включает переранжирование решений каждой высоты по

    score = Err + w · mean_λ |ln S_сол(λ) − ln S_ref(h, λ)| ,

где `w = --lidar-ratio-w` (0.5), `S = α/β` по общим длинам волн β и α.
Оценка S высоты — медиана по top-K решениям (`K = max(3G, 9)`); опорный
профиль `S_ref` строится по высотам: при ≥ 5 высот — кубическим
сглаживающим сплайном (`lam = 1.0`), иначе — скользящей медианой (окно 3).
Итераций — до `--lidar-ratio-iter` (3), досрочный выход при стабилизации
состава лучших `G`. Требует ≥ 2 высот и хотя бы одной общей λ; иначе —
предупреждение и ограничение не применяется (файл `lidar_ratios.txt` всё
равно создаётся, как в Python).

Отладочный вывод итераций ограничения: `CSOLVE_LIDAR_DEBUG=1` (в stdout).

Небольшое отличие от Python: `csolve` уважает `--no-plot` и в пакетном
режиме тоже (Python всегда рисует графики), поэтому PNG создаются только
без этого флага. Дополнительно C-версия строит сводные графики по высотам:
`refractive.png` (Re/Im на двух осях X), `error.png`, `volumes.png`,
`radii.png`, `concentration.png`, `sigma.png`, `lidar_ratios.png`.


## Проверка эквивалентности Python-версии

Скрипт запускает `solve` (эталон) и `csolve` с одинаковыми аргументами и
сравнивает JSON:

```bash
# из корня репозитория
.venv/bin/python csolve/tests/compare_reference.py --suite
# отдельный сценарий:
.venv/bin/python csolve/tests/compare_reference.py --tables base/average ...
```

Набор сценариев: `base/average`, `base_aggl/average`, `miedir --table-cback
4pi`, вход из JSON, `--gamma-select cv|err`, `--no-zero-boundary`,
`--no-smooth`, `--modes stat`, `--absolute`, `--nonneg`.

Пакетный режим сверяется отдельно:

```bash
.venv/bin/python csolve/tests/compare_reference.py --batch-suite
```

Сценарии: базовый пакет (2 высоты), `--lidar-ratio-cons`, он же с
`--lidar-ratio-w 0` (эквивалент потоковой обработки), `--modes stat`,
`miedir --table-cback 4pi`, и синтетический пакет из 7 высот (включает
ветку сглаживающего сплайна опорного профиля S). Сравниваются все
текстовые файлы (`moments.txt`, `refractive.txt`, `errors.txt`,
`lidar_ratios.txt`, `dist_*.txt`) по-токенно; PNG не сравниваются.

Допуски сверки: `rtol = 1e-6`, `atol = 1e-9` (для массивов коэффициентов `C`
`rtol = 1e-5` и нормировка на максимальный модуль вектора: на вырожденных
задачах NNLS выбирает разный активный набор). Фактически основные
величины совпадают точнее:

| Величина | Типичное расхождение |
|----------|----------------------|
| `r_um`, `channels.g*`, `best_solutions.err/gamma` | 1e-12…1e-14 |
| `best_solutions.C` | до 1e-5 от масштаба вектора (NNLS) |
| `moments.*` | ~1e-14 |
| `n_avg` | 1e-11 (base), 1e-8 (miedir, из-за переупорядочивания близких решений) |
| `modes.*` (со сглаживанием) | 1e-12 |
| пакетные текстовые файлы | совпадают в пределах `%g` (6 значащих цифр) |

Известные и объяснённые отличия:

- **`gamma` на плоском участке CV-критерия.** При выборе `--gamma-select cv`
  в некоторых окнах оценка LOO почти не зависит от `gamma` (различия ~1e-11
  абсолютных). На таком плато разные `gamma` дают одно и то же решение:
  `C` и `Err` совпадают, различается только `gamma`. Это отмечено в выводе
  скрипта как «gamma на плато CV».
- **Моды без сглаживания (`--no-smooth`).** Фит логнормали к несглаженному
  среднему численно неустойчив: изменения `n_avg` на уровне 1e-15
  относительных могут менять `rm`/`sigma` на проценты. Поэтому в сценарии
  `no-smooth` сравниваются `ok` и `method`, а не сами параметры.
- **`--nonneg`.** На границе ограничения `C ≥ 0` scipy (`lsq_linear`, TRF)
  оставляет компоненту ~1e-5 при масштабе `C ~ 1e8`; `csolve` (Lawson–Hanson)
  даёт точный 0. Решения физически эквивалентны: `n_avg`, моменты и моды
  совпадают до 1e-11…1e-13.

## Производительность

Замеры на Apple M1 (macOS), один и тот же набор аргументов, `--no-plot`:

| Сценарий | Python `solve` | `csolve` |
|----------|----------------|----------|
| `miedir`, 1 значение m, 256 точек r | 0.82 с | 0.06 с |
| `miedir`, 42 значения m, 256 точек r | 1.89 с | 0.62 с |
| `base/average`, 64 значения m, 256 точек r | 1.18 с | 0.89 с |
| `--batch`, 2 высоты, 64 значения m | 2.25 с | 0.33 с |

Разбивка времени `csolve` (`CSOLVE_TIME=1`): разбор таблиц ~0.25 с, таблицы
ядер ~0.03 с, матрицы `A` ~0.32 с, перебор и ансамбль — единицы миллисекунд.

  src/plot.c         два панно PNG через gnuplot
  src/cli.c          разбор аргументов (argtable3)
  src/main.c         сценарий: таблицы -> ядра -> A -> перебор -> вывод

## Ограничения

- только табличный режим: Mie-ядра (`miepython`) не переносились;
- `--noise` использует собственный ГПСЧ (xorshift + Бокс–Мюллер), поэтому
  при ненулевом шуме значения `g1` не совпадают с `numpy.default_rng`
  бит-в-бит (по умолчанию шум равен 0);
- для графика нужен `gnuplot`; подписи на английском, но содержат символы
  `µm`, `µm³/cm³`, `cm⁻³` — нужен шрифт с этими глифами (DejaVu Sans);
- вывод csolve на английском, а Python-версия печатает по-русски; поэтому
  скрипт сверки игнорирует строки-комментарии пакетных файлов и чисто
  текстовые поля JSON (`units_input`, `modes.*.method`);
- в пакетном режиме `csolve` уважает `--no-plot`, а Python-версия
  графики рисует всегда.

коэффициентов (обратное рассеяние `β` и ослабление `α`).

Полное описание программы: физическая постановка, метод, установка, все
режимы работы, форматы данных, параметры командной строки, устройство кода,
ограничения и примеры.

## 1. Назначение

Программа решает **обратную задачу лидарного зондирования**: по измеренным
коэффициентам обратного рассеяния `β` на нескольких длинах волн и
коэффициентам ослабления `α` восстанавливается распределение аэрозольных
частиц по размерам.

Восстанавливается **объёмное распределение**

```
F(r) = dV/dln r   [мкм³/см³]
```

(объём частиц с радиусом `r` на логарифмический интервал радиуса). Числовое
распределение `n(r) = dN/dr` получается из него пересчётом
`n(r) = F(r)·3/(4π r⁴)`.

Из распределения дополнительно вычисляются:

- числовая концентрация `N` [см⁻³];
- объёмная концентрация `C_v` [мкм³/см³];
- средний объём частиц `⟨V⟩` [мкм³];
- эффективный радиус `r_eff` [мкм];
- параметры логнормальных мод: `Vf, rm_f, σf` (fine, `r < r_split`),
  `Vc, rm_c, σc` (coarse, `r > r_split`) и общая оценка `V, rm, σ`;
- средний показатель преломления частиц `m_avg`.

## 2. Физическая постановка задачи

### 2.1 Измеряемые величины

Измеряются лидаром:

| Величина | Обозначение | Единицы | Смысл |
|----------|-------------|---------|-------|
| коэффициент обратного рассеяния | `β(λ)` | 1/(м·ср) | рассеяние назад на единицу длины на стерадиан |
| коэффициент ослабления | `α(λ)` | 1/м | ослабление луча на единицу длины |

Набор длин волн не зашит в код и полностью определяется входными данными.
В стандартном задании — 5 каналов:

- `β` на 355, 532, 1064 нм;
- `α` на 355, 532 нм.

### 2.2 Прямая задача

Измеренные коэффициенты связаны с распределением интегральными
уравнениями Фредгольма первого рода:

```
g_j = ∫ K_j(r) · n(r) dr,
```

где `g_j` — измеренный коэффициент `j`-го канала, `n(r) = dN/dr` — числовое
распределение, `K_j(r)` — ядро канала (сечение рассеяния частицы радиуса
`r` на единицу концентрации).

### 2.3 Ядра каналов

Для частицы радиуса `r` и длины волны `λ` параметр размера

```
x = 2π r / λ.
```

Ядра (в СИ):

| Канал | Ядро | Единицы |
|-------|------|---------|
| ослабление | `K_ext(λ, r) = π R² · q_ext(x)` | м² |
| обратное рассеяние | `K_back(λ, r) = (R²/4) · q_back(x)` | м²/ср |

Здесь `R = r·10⁻⁶` — радиус в метрах, `q_ext` и `q_back` — факторы
эффективности ослабления и обратного рассеяния (безразмерные), `x` —
параметр размера.

Соотношение для `K_back` следует из определения `q_back` в `miepython`:

```
q_back = |Σ_n (2n+1)(-1)ⁿ (a_n - b_n)|² / x² = 4|S(π)|²/x²,
C_back = |S(π)|²/k²  ⇒  C_back = q_back·r²/4
```

(проверено по рэлеевскому пределу; при `x → 0` ядро обратного рассеяния
переходит в классическое `K_back ≈ (8π/3)·(πR²)·(x⁴ …)` рэлеевской формулы).

Ядра вычисляются двумя способами:

1. **Mie-режим (по умолчанию)** — через библиотеку `miepython`
   (`Channel.kernel`), при фиксированном комплексном показателе преломления
   `m = Re(m) + i·Im(m)`, `Im(m) ≤ 0` (поглощающая среда).
2. **Табличный режим (`--tables`)** — из внешних таблиц сечений
   `C_ext(x)`, `C_back(x)` в мкм², снятых при `λ_ref = 2π` мкм
   (пересчёт на λ канала множителем `(λ/λ_ref)²`, см. раздел 7).

### 2.4 Связь объёмного и числового распределения

Программа работает с объёмным распределением `F = dV/dln r`:

```
dV/dln r = r · dV/dr = r · (4π/3) r³ · dN/dr = (4π/3) r⁴ · n(r),
```

откуда

```
n(r) = dN/dr = F(r) · 3/(4π r⁴) = q(r) · F(r),   q(r) = 3/(4π r⁴).
```

Ядра в матрице `A` умножаются на пересчётный фактор `q(r)`.

### 2.5 Единицы — сводка

| Величина | Единицы | Примечание |
|----------|---------|------------|
| `β` | 1/(м·ср) | входные данные |
| `α` | 1/м | входные данные |
| `K_ext` | м² | ядро |
| `K_back` | м²/ср | ядро |
| `r` | мкм | радиус (внутри переводится в м) |
| `F(r) = dV/dln r` | мкм³/см³ | выход |
| `n(r) = dN/dr` | см⁻³·мкм⁻¹ | пересчёт из F |
| `N` | см⁻³ | интегральная |
| `C_v` | мкм³/см³ | интегральная |

Переводы: 1 мкм = 10⁻⁶ м; 1 мкм² = 10⁻¹² м²; 1 мкм³/см³ = 10⁶ мкм³/м³.

## 3. Метод решения

### 3.1 Базис B-сплайнов

Искомая функция ищется на окне `[r0, r1]` в виде разложения

```
F(r) = Σᵢ Cᵢ Bᵢ(r),   r ∈ [r0, r1],
```

где `Bᵢ` — **зажатые (clamped) B-сплайны** степени `k ∈ {1,2,3,4}` на
логарифмически эквидистантной сетке узлов. Число базисных функций по
умолчанию равно числу измерений `M` (для задания — 5); настраивается флагом
`--n-basis N`.

**Граничные условия.** Из базиса исключаются первая и последняя функции
(`B₀`, `B_{M-1}`) — в зажатом базисе только они отличны от нуля на концах
интервала. Поэтому любое разложение обращается в ноль на границах:
`F(r0) = F(r1) = 0`. В разложении остаётся `N − 2` функции (при `N = 5` —
три). Отключить — `--no-zero-boundary`.

**Вырожденный случай.** При `M = 5` и степени 4 внутренних узлов не
остаётся — базис вырождается в полиномы Бернштейна степени 4 на весь
интервал (корректный предельный случай).

### 3.2 Матрица A (прямая задача на окне)

```
A[j, i] = ∫_{r0}^{r1} K_j(r) · q(r) · B_i(r) dr,
```

квадратуры Гаусса–Лежандра дробятся по узлам базиса и логарифмическим
подсегментам (`--log-span`), чтобы разрешить осцилляции ядер Mie.

### 3.3 МНК с регуляризацией по кривизне

```
min ||W (A C − g1)||² + γ² ||L C||²,
```

`L` — матрица вторых разностей коэффициентов (`L[i] = (1, −2, 1)`).
Веса `W = 1/g1` по умолчанию (относительная невязка, согласована с `Err`;
при `--absolute` веса единичные). При `--nonneg` — ограничение `C ≥ 0`
(тогда и `F(r) ≥ 0`).

### 3.4 Выбор параметра регуляризации γ

- `--gamma-select fixed` (по умолчанию): `γ = γ_rel · ||A||₂`,
  `γ_rel = --gamma-rel` (по умолчанию 0.1). Одинаковая нормировка для всех
  окон.
- `--gamma-select cv`: leave-one-out кросс-валидация по относительной
  невязке (защита от переобучения). LOO вычисляется закрытой формулой
  (`y_i − pred_i = (y_i − p_i)/(1 − k_i s_i)`, `s_i = a_iᵀ M⁻¹ a_i`), т.е.
  без пересчёта МНК по каждой исключённой строке — дёшево в батчевом режиме.
- `--gamma-select err`: минимум невязки `Err` (при числе измерений = числу
  неизвестных вырождается в точную интерполяцию).

### 3.5 Невязка

```
Err = Σᵢ |gᵢ − g1ᵢ| / g1ᵢ
```

— критерий качества окна (относительная, `g1 > 0`).

### 3.6 Ансамбль решений

1. Перебираются **окна** `(r0, r1)` (лог-сетки `--r0-*`, `--r1-*`
   с фильтром `r1 ≥ min_ratio·r0`), **степени** сплайнов `--degree` и
   **сетка показателя преломления** `m = --m-reals × --m-imags`.
2. Для каждого `m` строится своя таблица ядер (или загружаются свои
   внешние таблицы сечений).
3. Решения ранжируются по невязке `Err`.
4. Берутся `G = --best` решений с наименьшей невязкой; по каждому
   восстанавливается `F(r)`.
5. Итоговая функция — **среднее по покрытию**: в точке `r` усредняются
   только решения, чьё окно содержит `r` (точки вне всех окон — `NaN`).
6. Итоговый показатель преломления — среднее комплексных `m` по тем же
   `G` лучшим решениям.

### 3.7 Сглаживание среднего

Поточечное среднее решений изломается на границах окон. Ступенчатая
зависимость сглаживается кубическим сглаживающим сплайном
(`scipy.interpolate.make_smoothing_spline`) в нормированных координатах
(аргумент — `ln r` в [0,1], значения — `F/max|F|`), поэтому относительный
параметр `--smooth-lam` (по умолчанию `1e-4`) безразмерен. Веса точек —
кратность покрытия; крайние точки притягиваются к сырым значениям.
Отключить — `--no-smooth`.

### 3.8 Анализ мод

По усреднённому распределению на логнормальные моды (в `dV/dln r`):

- **fine** — `r ∈ [r_cov_min, r_split]`;
- **coarse** — `r ∈ [r_split, r_cov_max]`;
- **общая** — одна логнормаль по всему покрытому диапазону.

`V` — интеграл `F` по диапазону; `rm`, `σ` — из взвешенного МНК-фита
логнормали в координатах `(ln r, ln F)`. При вырождении фита (например,
бимодальная суммарная форма) `rm`, `σ` оцениваются по объёмным моментам.
Способ: `--modes fit|stat|auto` (auto — фит, при неудаче моменты).

## 5. Режимы работы

Программа поддерживает три режима:

| Режим | Флаг | Что делает |
|-------|------|------------|
| **Демо** | (без `--data`) | синтезирует «истинное» распределение, считает модельные `g1` через Mie-ядра и восстанавливает их; на график выводится истинное распределение для сравнения |
| **Одиночный (реальные данные)** | `--data data.json` | решает обратную задачу по одному набору измерений из JSON |
| **Пакетный** | `--batch measurements.txt` | обрабатывает все высоты из одного txt-файла, таблица ядер и матрицы `A` строятся один раз на весь пакет |

В любом режиме может быть включён **табличный режим ядер** (`--tables`, см.
раздел 7) вместо Mie.

## 6. Форматы входных данных

### 6.1 JSON (одиночный режим, `--data`)

```json
{
  "m": {"real": 1.45, "imag": -0.005},
  "backscatter": {
    "wavelengths_nm": [355, 532, 1064],
    "coefficients": [1.24e-5, 1.33e-5, 8.75e-6]
  },
  "extinction": {
    "wavelengths_nm": [355, 532],
    "coefficients": [3.78e-4, 4.10e-4]
  }
}
```

- `m` — **априорная оценка** показателя преломления. Не подставляется в
  ядра напрямую, а задаёт центр сетки перебора: при отсутствии явных
  `--m-reals/--m-imags` строится сетка
  `Re ∈ {0.95, 1.0, 1.05}·Re(m₀)`, `Im ∈ {−|Im(m₀)|, −|Im(m₀)|/2, 0}`.
- Единицы коэффициентов согласованы: `β` — 1/(м·ср), `α` — 1/м.
- Поле `units` — справочное, не конвертируется.
- Все коэффициенты должны быть `> 0`.
- Готовый пример — `examples/input_example.json`.

### 6.2 Пакетный txt (`--batch`)

```txt
Altitude  b355  b532  b1064 a355  a532
100       9.879211342818602e-06 1.06715705204743e-05  7.002700027432126e-06 0.000302238873845872  0.000327611920803267
...
```

- первая строка — заголовок `Altitude` + имена каналов;
- имя `b<нм>` → обратное рассеяние `β`, `a<нм>` → ослабление `α`;
- длина волны берётся из имени (355, 532, 1064 и т.п.);
- единицы — как в JSON (`β` 1/(м·ср), `α` 1/м);
- высот может быть сколько угодно; канальный набор один на пакет;
- пример — `tests/data/measurements_example.txt`.

Высоты независимы: таблица ядер и матрицы `A` строятся один раз на пакет,
а дальше каждая высота — только МНК по готовым `A`. Без
`--lidar-ratio-cons` высоты обрабатываются потоково (решения сразу
финализируются и освобождаются), поэтому пик памяти не растёт с числом
высот; при включённом ограничении решения всех высот удерживаются в памяти —
они нужны для переранжирования.

## 7. Табличный режим ядер (`--tables`)

Позволяет подать внешние таблицы сечений `C_ext(x)` и `C_back(x)` (в мкм²)
как функции параметра размера `x`, снятые при **эталонной длине волны
`λ_ref = 2π` мкм** (при этом абсцисса `x = 2πr/λ_ref` численно равна радиусу
`r` в мкм), вместо расчёта через `miepython`. Таблицы задают физическую
модель частиц (включая показатель преломления `m`) напрямую; `m` в ядрах не
участвует и используется только как метка каталога.

Таблицы берутся в формате, который создают `mkbase` (раздел 8) и
`mkbase_spheres`; `--tables` указывает на `base/average` (агрегат по формам)
или `base/shapeNN` (одна форма).

Поскольку сечение ∝ λ², при использовании на длине волны канала `λ` оно
пересчитывается как `C·(λ/λ_ref)²`; `λ_ref` задаётся `--table-ref-lambda-um`
(по умолчанию `2π`). Для 355/532/1064 нм множитель равен примерно
3.19·10⁻³ / 7.17·10⁻³ / 2.87·10⁻².

### 7.1 Структура каталога

`--tables` указывает на каталог с подкаталогами
`mre_<real:.2f>_mim_<imag:.5f>` (например `base/average` или `base/shapeNN`).
В каждом подкаталоге — один файл `data.txt` с таблицей сечений:

```
base/average/
  mre_1.45_mim_0.00000/
    data.txt
  mre_1.45_mim_0.01680/
    data.txt
  ...
```

- имя каталога — `mre_<real:.2f>_mim_<imag:.5f>`, как в `mkbase`;
  отрицательный ноль нормализуется (`mim_0.00000`, а не `mim_-0.00000`);
- `data.txt` — таблица с заголовком
  `# x Cext Cabs Cback Qext Qabs Qback [n]`. Читаются колонки `x`, `Cext`
  (ослабление) и `Cback` (обратное рассеяние); **выбор по имени колонки**,
  поэтому лишние столбцы (`n` в `average/`) и их порядок значения не имеют;
  `Cabs`/`Q*` не используются (в данных ADDA `Cabs` может быть
  отрицательным);
- комментарии (`#`, в т.ч. `# Units: ...` и `# Smoothed ...` у
  `mkbase_spheres`) и пустые строки игнорируются; заголовок распознаётся по
  строке, у которой первый токен после `#` равен `x`;
- `x` строго возрастает, `C > 0`, точек не меньше трёх;
- таблица снята при `λ_ref`; на длине волны канала сечение пересчитывается
  множителем `(λ/λ_ref)²`;
- **`C_back` — дифференциальное сечение на стерадиан** `dσ/dΩ(180°)`
  (согласовано с `β` [1/(м·ср)]). Так его пишут `mkbase` (ADDA: `s11(θ) =
  dσ/dΩ`, проверяется по `∫s11 dΩ = Csca`) и исправленный `mkbase_spheres`.
  Старые таблицы `mkbase_spheres`/`miedir` содержат `4π·dσ/dΩ` — для них
  нужен `--table-cback 4pi`; перепутанная конвенция даёт ошибку ровно в `4π`
  и уводит восстановление в мелкие радиусы;
- отсутствие каталога для нужного `m` — ошибка со списком доступных `m`;
- `--tables` должен указывать на `base/average` или `base/shapeNN`, а не на
  корень `base` (`average/` + `shape*/`): иначе выдаётся ошибка с подсказкой;
- выход `x` за пределы таблицы — ошибка; экстраполяция только с
  `--table-extrapolate` (граничной кривой, с предупреждением).

### 7.2 Ограничение по радиусу (покрытие x)

`x = 2πr/λ` ⇒ максимальный радиус канала `r_max = x_max·λ/(2π)`. Например,
при `x_max = 82`:

| λ, нм | r_max, мкм |
|-------|-----------|
| 355   | 4.63 |
| 532   | 6.94 |
| 1064  | 13.9 |

Эффективный предел окон `r1_max` — минимум по всем каналам (при `x_max=82`
это 4.63 мкм — каналы 355 нм «режут» диапазон). Код:

- автоматически урезает `r1_max` (диагностика по каналам печатается);
- при `r1_max < r1_min` выдаёт ошибку: расширьте таблицы по `x` или
  уменьшите `--r1-min`.

### 7.3 Ансамбль по m

Сетка перебора **берётся из таблиц**: сканируются подкаталоги
`mre_<real>_mim_<imag>/`, и перебор идёт только по значениям, для которых
есть `data.txt`. Флаги `--m-reals/--m-imags` (если заданы) **сужают**
этот набор; комбинации без таблиц в перебор не попадают (пустой результат —
ошибка со списком доступных `m`).

Для каждого `m` сетки загружается свой набор таблиц, решения ранжируются
по `Err`, `m_avg` усредняется по `G` лучшим — как в Mie-режиме. Если в
`--tables` есть `N` значений `m`, а `--m-reals/--m-imags` не заданы, то
перебираются все `N` (время расчёта растёт пропорционально).

В демо-режиме (без `--data`) «истинный» `m` тоже выбирается из табличных:
если `--m-real/--m-imag` не заданы — ближайший к `1.45 − 0.005j`; если
заданы оба — значение должно быть среди табличных, иначе ошибка.

### 7.4 Интерполяция

Выполняется в логарифмических координатах `(ln x, ln C)` **кубическим
сплайном** (как в `KernelTable`). Шаг таблицы по `x` должен разрешать
осцилляции (рипл) факторов Mie: при крупном шаге (`max Δx > 1`) выдаётся
предупреждение.

Предупреждения недостаточно: при `Δx ≳ 0.5` медианная ошибка ядра мала, но в
резонансах ядро отличается в разы, а инверсия к этому чувствительна.
Практика — `Δx ≲ 0.1` в верхней части диапазона: для `x = 0.01…80` это
≈ 8000 узлов (`mkbase_spheres --nx 8000`), для `x = 0.3…34` —
`mkbase --nx 500` (раздел 8.4). Сглаживание (`mkbase_spheres --smooth`)
убирает рипл и тоже смещает результат — для ядер лучше без него.
Проверить конкретную базу: `python tests/compare_tables_mie.py <каталог>`.

### 7.5 Демо в табличном режиме

Без `--data` демо-режим синтезирует измерения из таблиц опорного `m`
(функция `demo_true_distribution` интегрируется через табличные ядра).

## 8. Сборка базы сечений (`mkbase`)

Утилита **`mkbase`** (пакет `src/mkbase/`) собирает **базу сечений** из
каталога с результатами расчётов ADDA (рассеяние на частицах методом
дискретных диполей). База — плоские таблицы
`x, Cext, Cabs, Cback, Qext, Qabs, Qback` по формам частиц и показателям
преломления; входит в тот же пакет, что и `solve`.

Выход утилиты — готовый вход для `solve --tables`: `--tables base/average`
(агрегат по формам) или `--tables base/shapeNN` (одна форма).

```bash
mkbase results_aggl -o base                       # console-script
uv run mkbase results_aggl -o base                # через uv
python src/mkbase/mkbase.py results_aggl -o base  # без установки

# переинтерполировать все таблицы на лог-эквидистантную сетку из 60 узлов
uv run mkbase results_aggl -o base --nx 60
```

`results` — каталог результатов расчётов; `-o/--out` — каталог базы (по
умолчанию `base`; в репозитории игнорируется git). `-n/--nx N` — число узлов
лог-эквидистантной сетки `x` (раздел 8.4).

### 8.1 Вход

```
results_aggl/
  shapeNN/                                   # форма частицы
    mr<real>/                                # Re(m)
      mi<imag>/                              # Im(m)
        shapeNN_mr<real>mi<imag>_x<X>[eps3]/
          CrossSec   mueller   log   log_orient_avg
```

| Величина | Источник |
|----------|----------|
| `Shape`, `mre`, `mim` | из имён каталогов (`shape01`, `mr1.30`, `mi0.00215`) |
| `x` | из имени листового каталога — суффикс `_x<число>` («size along x-axis»); маркер `eps3` (запуск `adda … -eps 3`) отбрасывается |
| `Cext`, `Cabs` | файл `CrossSec` |
| `Cback` | последнее значение столбца `s11` файла `mueller` (θ = 180°, обратное рассеяние) |
| `Qext`, `Qabs`, `Qback` | `C / (π·x²)` |

Сбойные прогоны (нет `CrossSec`/`mueller`) и каталоги без ожидаемого имени
пропускаются с предупреждением в `stderr`.

### 8.2 База

```
base/
  shapeNN/
    mre_<real>_mim_<imag>/
      data.txt
  average/
    mre_<real>_mim_<imag>/
      data.txt
```

- `mre` — 2 знака после запятой, `mim` — 5;
- `data.txt` — значения через пробел, строки по возрастанию `x`, первая строка —
  заголовок:

```
# x Cext Cabs Cback Qext Qabs Qback
0.2951128 2.667137275e-07 3.732907645e-28 3.1659075995e-08 9.748e-07 1.364e-27 1.157e-07
...
```

### 8.3 Агрегат по формам (`average/`)

Для каждого `(mre, mim)` дополнительно строится среднее по всем формам:

- каждая форма интерполируется на общую **каноническую сетку** `x` (узлы,
  присутствующие во всех формах хотя бы одного `(mre, mim)`), затем значения
  усредняются арифметически (равные веса);
- интерполяция — **кубический сплайн в лог-лог** (как в `TabularCrossSection`);
  для каналов с `C ≤ 0` (например `Cabs` при `mim = 0`) — линейная;
- добавляется столбец `n` — число усреднённых форм:

```
# x Cext Cabs Cback Qext Qabs Qback n
```

Если исходные сетки `x` у разных форм не совпадают (в `results_aggl` узел 8 у
части прогонов задан как `mre + 0.0076925` вместо геометрического значения),
печатается предупреждение со списком неканонических `x`, а сами значения
интерполируются на общую сетку.

### 8.4 Лог-эквидистантная сетка (`--nx`)

По умолчанию узлы `x` таблиц — это исходные узлы расчётов ADDA (раздел 8.2),
а `average/` интерполируется на их общее подмножество. Флаг `--nx N` заменяет
это на **лог-эквидистантную сетку из `N` узлов** (геометрическая прогрессия,
`np.geomspace`) для каждой группы `(mre, mim)` отдельно:

- диапазон сетки — `[min x, max x]` по **всем** точкам всех форм группы;
- на неё переинтерполируются и пошape-таблицы `shapeNN/`, и агрегат
  `average/` — все таблицы группы лежат в одних и тех же узлах `x`;
- интерполяция та же, что при усреднении: кубический сплайн в лог-лог,
  линейная для каналов с `C ≤ 0`; узлы вне диапазона конкретной формы
  пропускаются (для формы печатается предупреждение, в `average` такой узел
  усредняется по меньшему числу форм — столбец `n`);
- расхождение исходных сеток между формами перестаёт быть проблемой, поэтому
  предупреждение о неканонических `x` в этом режиме не выводится;
- крайние узлы сетки совпадают с `min x`/`max x` группы; при `nx ≥ 2`
  (условие проверяется в `--nx`), вырожденная группа с единственным `x` даёт
  одну строку и предупреждение;
- по умолчанию (`--nx` не задан) поведение прежнее — канонические узлы.

Режим удобен, чтобы `solve --tables` видел одинаковые абсциссы у всех форм и
не зависел от неоднородности сеток ADDA.

## 10. Выходные данные

### 10.1 Экран

- таблица лучших решений (ранг, `m`, степень, `r0`, `r1`, `γ`, `Err`);
- средний показатель преломления `⟨m⟩`;
- `F = dV/dln r` в ключевых точках;
- согласие по каналам `g` vs `g1` (относительные ошибки);
- интегральные характеристики (раздел 3.1);
- параметры мод.

### 10.2 Интегральные характеристики

| Величина | Формула | Единицы |
|----------|---------|---------|
| объёмная концентрация `C_v` | `∫ F dln r` | мкм³/см³ |
| числовая концентрация `N` | `∫ F·3/(4πr⁴) dr` | см⁻³ |
| средний объём частиц `⟨V⟩` | `C_v / N` | мкм³ |
| эффективный радиус `r_eff` | `∫r³n dr / ∫r²n dr` | мкм |

(`F ≥ 0` по физ. смыслу; по покрытой лучшими решениями области.)

### 10.3 График (`result.png`)

Два панно: log-log `dV/dln r` (мкм³/см³) — лучшие решения, сглаженное
среднее, «истинное» (в демо), сырое среднее пунктиром; и сравнение `g1` с
расчётными `g`. На первом панно — `⟨m⟩`.

### 10.4 JSON (`--json`)

Полные результаты: `m_avg`, моменты, моды, сетка `r`, `n_avg` (сглаженное),
`n_avg_raw` (сырое), список решений (m, k, r0, r1, γ, Err, коэффициенты C),
`g_fit` по каналам.

### 10.5 Пакетный режим

В каталог `--batch-out-dir` (`moments.txt`, `refractive.txt`, `errors.txt`,
`lidar_ratios.txt` — по строке на высоту, плюс `dist_<H>.txt` и
`plot_<H>.png` на высоту):

| Файл | Содержимое (строка на высоту) |
|------|-------------------------------|
| `dist_<H>.txt` | `r, мкм | dV/dln r, мкм³/см³` + комментарии |
| `moments.txt` | `H Vf Vc V rmf rmc rm reff N sigma_f sigma_c sigma` |
| `refractive.txt` | `H Re(m) Im(m)` |
| `errors.txt` | `H |β_fit−β|/β ... Err` |
| `lidar_ratios.txt` | `H S_<нм> ...` (при `--lidar-ratio-cons`) |
| `plot_<H>.png` | график распределения и согласия для высоты |

## 11. Устройство кода

```
src/solve/
  __init__.py   CLI (main), парсинг данных, демо, график, JSON I/O,
                моменты, анализ мод
  batch.py      пакетная обработка (--batch), ограничение лидарного отношения
  kernels.py    каналы, Mie-ядра (miepython), табличные сечения (--tables),
                KernelTable с интерполяцией
  basis.py      B-сплайны на лог-сетке, квадратуры Гаусса–Лежандра,
                матрица A, кэш геометрии окна (window_geometry)
  inverse.py    регуляризованный МНК, выбор γ, перебор окон, ансамбль,
                сглаживание, предвычисление матриц A (DesignSet)
src/mkbase/     сборка базы сечений (console-script mkbase; раздел 8)
tests/          проверки (см. раздел 14)
examples/       пример входных данных
docs/           эта документация
```

### Ключевые классы и функции

**`kernels.py`**
- `Channel(kind, wl_um, table=None)` — канал (`alpha`/`beta`); `kernel(m, r)`
  возвращает ядро; при `table` не None — берёт сечение из таблицы.
- `TabularCrossSection` — внешняя таблица `C(x)` в мкм² (лог-log кубическая
  интерполяция, контроль диапазона x); `from_data_file(path, column, ...)`
  читает `data.txt` формата `mkbase` и выбирает колонку по имени.
- `m_table_dirname(m)` — имя каталога `mre_<real:.2f>_mim_<imag:.5f>`.
- `load_table_channels(root, m, channels, extrapolate)` — загрузка таблиц из
  каталога `mre_<real>_mim_<imag>/data.txt` + расчёт `r_max_cap`.
- `KernelTable(m, channels, r_min, r_max, dx_max)` — плотная таблица ядер с
  кубической интерполяцией в `(ln r, ln K)`; `kernels(r)` — все каналы сразу.
- `dvol_dlnr_factor(r)` — `q(r) = 3/(4πr⁴)`.
- `set_mie_jit(use_jit)` / `mie_jit_enabled()` — переключение бэкенда
  miepython (numba/Python).

**`basis.py`**
- `clamped_knots`, `bspline_basis` — зажатый B-сплайновый базис;
- `quadrature_grid` — составная квадратура Гаусса–Лежандра (кэш);
- `design_matrix` — матрица `A` для одного окна;
- `window_geometry` — кэш геометрии окна (узлы/веса квадратуры,
  значения базиса, множитель `q(r)`), не зависит от `m` и от `g1`.

**`inverse.py`**
- `Solution` — одно решение (m, степень, r0, r1, γ, C, базис, err, g_fit);
- `DesignSet` / `build_design` — матрицы `A` сразу для всех `(m, окно)`
  и их нормы `‖A‖₂`, переиспользуются для всех высот в пакетном режиме;
- `solve_regularized`, `cv_error` — МНК с регуляризацией, LOO-CV
  (эталонный пересчёт без каждой строки);
- `_cv_score_batched` — LOO-CV закрытой формулой, батчево по окнам;
- `scan_variants` — полный перебор (m, окна, степени);
- `ensemble_average` — усреднение по G лучшим + сглаживание;
- `smooth_distribution` — сглаживающий сплайн.

**`__init__.py`**
- `channels_from_data(data)` — каналы из JSON;
- `forward_measurements(...)` — прямое моделирование `g1` (для демо);
- `size_moments`, `mode_analysis` — интегральные характеристики и моды;
- `main()` — точка входа CLI.

**`batch.py`**
- `parse_batch_txt` — парсинг пакетного txt;
- `run_batch` — полный цикл пакетной обработки;
- `_build_kernel_tables` — таблицы ядер один раз на пакет (Mie или табличный
  режим);
- `_build_design` — матрицы `A` один раз на пакет (батчевый МНК по высотам);
- ограничение плавности лидарного отношения.

## 12. Ограничения и рекомендации

1. **Разрешение.** С 5 измерениями и 5 базисными функциями
   восстанавливается только гладкая огибающая распределения: узкие моды
   (`ln σ ≲ 0.4–0.5`) «размазываются», амплитуда в центрах мод занижается.
   Для более узких мод — увеличивайте число каналов или подбирайте сетку
   окон под ожидаемый диапазон размеров.
2. **m восстанавливается с точностью до шага сетки** `--m-reals ×
   --m-imags`; если оптимум на границе сетки — расширьте её. Время расчёта
   растёт пропорционально числу значений m.
3. **Интегралы занижаются** из-за сглаживания (амплитуда F занижается).
   Граничные условия `F(r0)=F(r1)=0` (по умолчанию) убирают фиктивный хвост
   и заметно повышают точность `⟨V⟩` и `r_eff`. Используйте `--nonneg` и
   более широкую сетку окон.
4. **Недоопределённость.** При `N−2 >` числа каналов система
   недоопределена — решение опирается на регуляризацию (выдаётся
   предупреждение).
5. **Параметры мод** оцениваются по сглаженному среднему: σ обычно
   завышается, rm смещается к центру масс. Это фундаментальное ограничение
   постановки, не ошибка алгоритма.
6. **Табличный режим:** покрытие по `x` ограничивает диапазон радиусов
   (раздел 7.2); таблицы должны быть достаточно плотны по `x` (рипл Mie).

## 15. Частые вопросы

**Почему `Err` не равен нулю даже на «идеальных» данных?**
С 5 измерениями и 3–5 неизвестными на окно система недоопределена или
переопределена с учётом регуляризации; кроме того, модельные окна не вполне
описывают распределение на всей оси. Ненулевая «обучающая» невязка — норма
для регуляризованной инверсии.

**Почему восстановленное `⟨V⟩` и `r_eff` неточны?**
Из-за эффекта сглаживания амплитуда F занижается (см. раздел 12, п.3).
Включайте `--nonneg` и граничные условия (по умолчанию включены).

**В каких единицах подавать `C_back` в таблицах?**
В мкм² **на стерадиан** (дифференциальное сечение), иначе разделите на `4π`.

**Таблицы обрезаются на `x=82` — как обработать крупные частицы?**
Код автоматически ограничивает `r1_max` минимумом покрытия по каналам
(при 355 нм и x_max=82 это 4.63 мкм). Либо расширяйте таблицы по x, либо
сужайте ожидаемый диапазон радиусов (`--r1-max`).

**Почему печатается предупреждение «крупный шаг по x»?**
Шаг таблицы больше `Δx = 1` — осцилляции (рипл) факторов Mie могут быть не
разрешены интерполяцией. Увеличьте плотность точек по x.
